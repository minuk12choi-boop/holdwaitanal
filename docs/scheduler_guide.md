# Windows 작업 스케줄러 설정 가이드

## 0. 준비

`scripts/` 폴더에 실행 래퍼가 있다. `git pull` 후 확인.

```
D:\PERSONAL_SPACE\SW\python\7_holdwaitanal\scripts\run_build_f3.bat
D:\PERSONAL_SPACE\SW\python\7_holdwaitanal\scripts\run_get_move.bat
```

보이지 않으면 `git pull` 을 먼저 한다. 탐색기에서 안 보이면
"보기 → 파일 확장명" 을 켠다(`.bat` 이 숨겨져 있을 수 있다).

먼저 **직접 더블클릭해서 정상 동작하는지 확인**한다. 창이 바로 닫히면
`logs\build_f3.log` 를 열어 오류를 본다.

## 1. build_f3 — 2시간마다

작업 스케줄러 → **작업 만들기**(기본 작업 만들기 아님)

### 일반
- 이름: `holdwaitanal_build_f3`
- **사용자가 로그온했는지 여부에 관계없이 실행** 선택
- **가장 높은 수준의 권한으로 실행** 체크

### 트리거 → 새로 만들기
- 작업 시작: `일정에 따라` → `매일`
- 시작: 오늘 날짜, 시간 **`00:00:00`**
- **고급 설정**
  - `작업 반복 간격` 체크 → **`2시간`**
  - `기간` → **`1일`**

06 / 14 / 22시에 정확히 걸리려면 시작 시각이 짝수 정각이어야 한다.
`00:00` 시작 + 2시간 간격이면 00, 02, 04, 06, 08 ... 22 로 떨어진다.

### 동작 → 새로 만들기
- 동작: `프로그램 시작`
- 프로그램/스크립트: `D:\PERSONAL_SPACE\SW\python\7_holdwaitanal\scripts\run_build_f3.bat`
- **시작 위치(옵션)**: `D:\PERSONAL_SPACE\SW\python\7_holdwaitanal`

시작 위치를 비우면 `C:\Windows\System32` 에서 실행돼 `.env` 를 못 찾는다.
(래퍼가 `cd /d "%~dp0.."` 로 보정하지만 함께 지정해 두는 것이 안전하다.)

### 설정
- `작업이 이미 실행 중이면 다음 규칙 적용` → **`새 인스턴스 시작 안 함`**
- `작업이 실패하는 경우 다시 시작 간격` → `10분`, `3회`

## 2. get_move — 매일 22:30

동일한 방식으로 하나 더 만든다.

- 이름: `holdwaitanal_get_move`
- 트리거: `매일`, 시작 **`22:30:00`** (반복 없음)
- 프로그램: `...\scripts\run_get_move.bat`
- 시작 위치: 프로젝트 루트

22:00 에 업무일이 끝나므로 그 이후에 돌려야 마지막 `SW` shift 가 담긴다.

## 4. 확인

| 확인 대상 | 방법 |
|---|---|
| 실행 여부 | 작업 스케줄러 → 해당 작업 → `마지막 실행 결과` 가 `0x0` |
| 로그 | `logs\build_f3.log`, `logs\get_move.log` |
| 적재 여부 | 웹 `/api/health/` 에서 행수 확인 |
| 스냅샷 이력 | 웹 `다운로드` 페이지의 스냅샷 목록 |

`0x1` 이 뜨면 파이썬 오류다. 로그 파일 마지막 부분을 본다.
