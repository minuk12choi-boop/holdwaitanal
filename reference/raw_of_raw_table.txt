================================================================================
raw_of_raw_table.txt
  Spotfire 로딩용 Oracle 원본(raw) 테이블 조회 쿼리
================================================================================

[목적]
  기존: bdq -> datalake(Impala) 직접 조회
  변경: Spotfire 로 원본 DB 조회 -> S3 Drive 적재 -> python 이 S3 에서 읽어 전처리

  따라서 여기에는 **전처리가 전혀 없는 생테이블 조회**만 둔다.
  결합/윈도우/집계는 전부 python(build_f3.py, get_move.py)이 그대로 담당한다.

[조회 시각 확인]
  모든 쿼리에 query_time 컬럼을 둔다.

      TO_CHAR(SYSDATE, 'YYYY-MM-DD HH24:MI:SS') AS query_time

  Spotfire 가 실제로 원천을 다시 읽었는지(reload 됐는지) 확인하기 위한 것이다.
  업로드 시각만 보면 "같은 데이터를 다시 올린 것"과 구분되지 않는다.
  spotfire_s3_export.py 가 이 값을 upload_log 와 _manifest.json 에 기록한다.

  python 전처리는 이 컬럼을 쓰지 않는다(f3 출력 컬럼 목록에 없어 자동 제외).

[원칙]
  현재 build_f3.py / get_move.py 가 bdq 로 호출하던 **Impala 쿼리를 그대로
  Oracle 문법으로 옮긴다.** 그 쿼리들이 이미 로딩시간 기준으로 최적화된 형태다.

  - WHERE / JOIN 조건을 임의로 빼지 않는다.
      lot_status_seg, line = sys_line_id, lot_type, cur_line_id, owner,
      lot_transn_type, 라인 간 최신 last_event_date 선별 등 전부 유지.
  - 컬럼도 Impala 버전과 동일하게 실제 쓰는 것만 SELECT 한다.
  - 다만 Impala 전용 처리 두 가지는 뺀다.
      (1) impala_insert_time 기준 최신 적재분 선별 -> Oracle 원본에는 불필요
      (2) CAST / TO_TIMESTAMP / REGEXP_REPLACE 형변환 -> python 이 이미 담당
  - S3 에 올릴 때 아래 [S3 파일명] 을 그대로 쓰면 python 쪽 매핑이 단순해진다.

[대상 라인] PFR1(=smicdc_p3nrd), KFR7(=smicdc_nrdk)

-- 1) PFR1_KFR7_LOT_GRADE : mc_lot + mc_lot_attr(GRADE) + mc_lot_step_comment
--    *호출시간: 8초
--
--    [최적화 이력]
--    처음 이식본은 Impala 의 m -> c -> m0 -> m1 CTE 구조를 그대로 옮겼는데,
--    Oracle 에서 mc_lot 을 라인당 3회 읽는다(m 에서 1회, m0 의 재조인에서 1회,
--    m1 에서 다시 1회). 거기에 SELECT DISTINCT 까지 걸려 CPU 가 터졌다.
--
--    아래는 같은 결과를 내면서 스캔을 1회로 줄인 형태다.
--      - m/c/m0 3단 CTE  ->  MAX(...) OVER (PARTITION BY lot_id) 단일 패스
--      - SELECT DISTINCT ->  제거. 대신 조인 상대를 1:1 로 보장한다
--          grade : parent_object_id 기준 GROUP BY (중복 attr 방지)
--          co    : lot_id 기준 rn=1 (최신 코멘트 1건)
--
--    [원본과 동일하게 유지한 것]
--      - max_event_date 는 lot_status_seg 필터 '이전' 값으로 계산한다.
--        (Active/Hold 가 아닌 행이 더 최신이면 그 lot 은 빠지는 동작을 보존)
--      - order_seq 가 비어 있어도 받는다. PFR1 에서 그 lot 이 FabPlan 이다.
--      - line = sys_line_id, lot_type IN ('PP','PG','EG'),
--        cur_line_id NOT IN ('CHTV')
--
--    materialworkstatus 는 datasource 가 달라 #2 로 분리. python 이 (line, lot_id)
--    로 붙인다.
--
--    [dest_line_id]
--    smimes.mi_current_wip_v 를 lot_id 로 LEFT JOIN 해 목적지 라인을 붙인다.
--    KFR7 테이블에 NRD-K 와 NRD 가 함께 들어와 있어, python 이 이 값으로 가른다.
--      KFR7 + dest_line_id IN ('KFR7A','KFR7B') -> KFR7 (NRD-K)
--      KFR7 + dest_line_id IN ('KFR7C','KFR7D') -> KFR4 (NRD)
--    그 외 값은 기존 분류를 그대로 따른다.
--------------------------------------------------------------------------------
WITH lot AS (
    SELECT 'PFR1' AS line, object_id, sys_line_id, cur_line_id, origin_line_id,
           lot_id, carr_id, lot_type, lot_level, cur_qty, bay_name,
           lot_status_seg, step_status_seg, proc_id, order_seq, step_seq,
           start_date, last_tkout_date, step_arrive_date, last_event_date
    FROM   smicdc_p3nrd.mc_lot
    UNION ALL
    SELECT 'KFR7' AS line, object_id, sys_line_id, cur_line_id, origin_line_id,
           lot_id, carr_id, lot_type, lot_level, cur_qty, bay_name,
           lot_status_seg, step_status_seg, proc_id, order_seq, step_seq,
           start_date, last_tkout_date, step_arrive_date, last_event_date
    FROM   smicdc_nrdk.mc_lot
),
lot_rank AS (
    SELECT l.*,
           MAX(last_event_date) OVER (PARTITION BY lot_id) AS max_event_date
    FROM   lot l
),
grade AS (
    SELECT 'PFR1' AS line, parent_object_id, MAX(attr_value) AS grade
    FROM   smicdc_p3nrd.mc_lot_attr
    WHERE  attr_name = 'GRADE'
    GROUP  BY parent_object_id
    UNION ALL
    SELECT 'KFR7' AS line, parent_object_id, MAX(attr_value) AS grade
    FROM   smicdc_nrdk.mc_lot_attr
    WHERE  attr_name = 'GRADE'
    GROUP  BY parent_object_id
),
wip AS (
    -- 목적지 라인. KFR7 안에 NRD-K / NRD 가 섞여 있어 이 값으로 가른다.
    SELECT lot_id, dest_line_id
    FROM   smimes.mi_current_wip_v
    WHERE  line_id IN ('KFR7', 'PFR1')
      AND  dest_line_id IS NOT NULL
),
co AS (
    SELECT line, lot_id, lot_inform
    FROM  (SELECT 'PFR1' AS line, lot_id, step_comment AS lot_inform,
                  ROW_NUMBER() OVER (PARTITION BY lot_id
                                     ORDER BY update_date DESC) AS rn
           FROM   smicdc_p3nrd.mc_lot_step_comment
           WHERE  parent_order_seq = 0
             AND  comment_type = 'LOT')
    WHERE  rn = 1
    UNION ALL
    SELECT line, lot_id, lot_inform
    FROM  (SELECT 'KFR7' AS line, lot_id, step_comment AS lot_inform,
                  ROW_NUMBER() OVER (PARTITION BY lot_id
                                     ORDER BY update_date DESC) AS rn
           FROM   smicdc_nrdk.mc_lot_step_comment
           WHERE  parent_order_seq = 0
             AND  comment_type = 'LOT')
    WHERE  rn = 1
)
SELECT
       TO_CHAR(SYSDATE, 'YYYY-MM-DD HH24:MI:SS') AS query_time,
      l.line,
       l.cur_line_id,
       l.sys_line_id,
       l.origin_line_id,
       l.lot_id,
       l.carr_id,
       l.lot_type,
       CASE WHEN NVL(g.grade, '-') <> '-' THEN 'G' || g.grade END      AS grade,
       l.lot_level,
       l.cur_qty,
       l.bay_name,
       CASE WHEN l.lot_status_seg = 'Hold' THEN 'HOLD'
            ELSE l.step_status_seg END                                 AS status,
       l.proc_id,
       l.order_seq,
       l.step_seq,
       l.start_date,
       l.last_tkout_date,
       l.step_arrive_date,
       l.last_event_date,
       CASE WHEN l.origin_line_id <> l.sys_line_id THEN 'OLD_SEND'
            WHEN l.origin_line_id  = l.sys_line_id
             AND l.sys_line_id    <> l.cur_line_id THEN 'NEW_SEND'
       END                                                             AS sendfab,
       co.lot_inform,
       w.dest_line_id
FROM       lot_rank l
LEFT JOIN  grade g  ON g.line = l.line AND g.parent_object_id = l.object_id
LEFT JOIN  co       ON co.line = l.line AND co.lot_id = l.lot_id
LEFT JOIN  wip w    ON w.lot_id = l.lot_id
WHERE      l.last_event_date = l.max_event_date
  AND      l.lot_status_seg IN ('Active', 'Hold')
  AND      l.line = l.sys_line_id
  AND      l.lot_type IN ('PP', 'PG', 'EG', 'EE')
  AND      l.cur_line_id NOT IN ('CHTV')
  -- FabPlan lot 은 order_seq 가 비어 있다. 그것으로 FabPlan 을 가려내므로
  -- 여기서 거르면 안 된다(거르면 그 lot 이 화면에 아예 안 나온다).
;

-- 2) PFR1_KFR7_MATERIALWORKSTATUS : fa_object4  *호출시간: 7초
--    #1 과 datasource 가 달라 따로 부른다. 라인은 LINE 컬럼으로 구분한다.
--    python 이 lot 결과에 (line, lot_id) 로 LEFT JOIN 해 fa_object4 를 붙인다.
--------------------------------------------------------------------------------
SELECT TO_CHAR(SYSDATE, 'YYYY-MM-DD HH24:MI:SS') AS query_time,
       'PFR1' AS line,
       lotid  AS lot_id,
       fa_object4
FROM   smicdc_p3nrd.materialworkstatus
UNION ALL
SELECT TO_CHAR(SYSDATE, 'YYYY-MM-DD HH24:MI:SS') AS query_time,
       'KFR7' AS line,
       lotid  AS lot_id,
       fa_object4
FROM   smicdc_nrdk.materialworkstatus
;

--------------------------------------------------------------------------------
-- [UNION ALL 주의] 두 블록의 **컬럼 수와 순서가 같아야** 한다.
--    다르면 ORA-01789(부정확한 블록/열 수). QUERY_TIME 을 한쪽에만 넣어
--    생기는 실수가 잦다. 양쪽 첫 컬럼에 똑같이 둔다.
--------------------------------------------------------------------------------
-- 3) PFR1_KFR7_STEP_PATH: smicdc_p3nrd.mc_lot_step_path, smicdc_nrdk.mc_lot_step_path *호출시간: 62초
--    대상 lot(Active/Hold) 만 추리고 **order_seq 로는 자르지 않는다.**
--
--    [이유] lot 조회 시점과 이 쿼리의 mc_lot 조회 시점이 달라 order_seq 가
--    어긋난다. 그 상태로 `p.order_seq >= c.order_seq` 를 걸면 그 사이 진행된
--    lot 의 현스텝이 잘려 나간다(RUN 중인 스텝이 통째로 빠진다).
--    과거 스텝까지 다 받아 오는 대신, 현스텝 기준 자르기는 python 이 한다
--    (build_f3.narrow_step_to_scope). 두 값이 같은 스냅샷에서 나오므로
--    어긋나지 않는다.
--------------------------------------------------------------------------------
SELECT TO_CHAR(SYSDATE, 'YYYY-MM-DD HH24:MI:SS') AS query_time,
       'PFR1' AS line_id,
       p.lot_id,
       p.order_seq,
       p.proc_id,
       p.step_seq,
       p.step_desc,
       p.step_level,
       p.step_skip_yn,
       p.delay_step_type,
       p.delay_time_mins,
       p.layer_id,
       p.eqp_type,
       p.eqp_group_id,
       p.recipe_id,
       p.ext_1st_vals,
       p.tkin_type_detail
FROM   smicdc_p3nrd.mc_lot_step_path p,
       (SELECT DISTINCT lot_id
        FROM   smicdc_p3nrd.mc_lot
        WHERE  lot_status_seg IN ('Active', 'Hold')) c
WHERE  p.lot_id = c.lot_id

UNION ALL

SELECT TO_CHAR(SYSDATE, 'YYYY-MM-DD HH24:MI:SS') AS query_time,
       'KFR7' AS line_id,
       p.lot_id,
       p.order_seq,
       p.proc_id,
       p.step_seq,
       p.step_desc,
       p.step_level,
       p.step_skip_yn,
       p.delay_step_type,
       p.delay_time_mins,
       p.layer_id,
       p.eqp_type,
       p.eqp_group_id,
       p.recipe_id,
       p.ext_1st_vals,
       p.tkin_type_detail
FROM   smicdc_nrdk.mc_lot_step_path p,
       (SELECT DISTINCT lot_id
        FROM   smicdc_nrdk.mc_lot
        WHERE  lot_status_seg IN ('Active', 'Hold')) c
WHERE  p.lot_id = c.lot_id
;

-- 7) PFR1_KFR7_HOLD : memmss.fab_issue_lot *호출시간: 15초 (*fab_issue_lot의 datasource도 mc_lot과 달라서 분리해둠)
--     impala_insert_time 은 Impala 적재본 전용 컬럼이라 넣지 않는다.
--     version_desc 는 적재 스냅샷 ID 로 Oracle 원본에도 있다. 반드시 포함한다.
--     Impala 버전은 최신 version_desc + status_seq <> '2' + 재공 lot 조인까지
--     서버에서 걸었다. 같은 조건을 그대로 유지한다.
--------------------------------------------------------------------------------
SELECT
       TO_CHAR(SYSDATE, 'YYYY-MM-DD HH24:MI:SS') AS query_time,
      h.line_id,
       h.item_type,
       h.status_seq,
       h.lot_id,
       h.step_seq,
       h.hold_user_name,
       h.issue_reason_cont,
       h.issue_date,
       h.version_desc
FROM   memmss.fab_issue_lot h
WHERE  h.line_id IN ('KFR7', 'PFR1')
  AND  h.status_seq <> '2'
  AND  h.version_desc = (SELECT MAX(version_desc)
                         FROM   memmss.fab_issue_lot
                         WHERE  line_id IN ('KFR7', 'PFR1'))
;

-- 8) PFR1_KFR7_MOVE : SMIMES.MI_LOT_TRANSN_HIST  *호출시간: 9초
--     MOVE = TrackOut 매수. lot_type 은 PP/PB/PG 만.
--     line_id 는 cur/sys 합집합이라 sys_line_id 조건을 함께 건다.
--     기간은 Spotfire 파라미터로 바꿔 쓴다(아래는 최근 3일).
--     컬럼명은 기존 Impala 버전과 동일하게 맞춘다(python 전처리를 그대로 쓰기 위함).
--       lot_transn_time   -> tkout_date          TO_DATE 로 DATE 변환
--       recent_tkout_time -> recent_tkout_date   TO_DATE 로 DATE 변환
--       current_line_id   -> cur_line_id
--       component_qty     -> move
--     python 은 db_common.to_datetime() 으로 받으므로 DATE 든 문자열이든 동작한다.
--------------------------------------------------------------------------------
SELECT
       TO_CHAR(SYSDATE, 'YYYY-MM-DD HH24:MI:SS') AS query_time,
      sys_line_id,
       line_id,
       current_line_id      AS cur_line_id,
       lot_id,
       lot_type,
       component_qty        AS move,
       ppid,
       process_eqp_id,
       process_id,
       step_seq,
       step_desc,
       eqp_type,
       to_date(substr(recent_tkout_time, 1, 15), 'yyyymmdd hh24:mi:ss')  AS recent_tkout_date,
       tkin_date,
       process_start_date,
       process_finish_date,
       to_date(substr(lot_transn_time, 1, 15), 'yyyymmdd hh24:mi:ss')    AS tkout_date
FROM   SMIMES.MI_LOT_TRANSN_HIST
WHERE  line_id     IN ('KFR7', 'PFR1')
  AND  sys_line_id IN ('KFR7', 'PFR1')
  AND  lot_transn_type = 'TrackOut'
  AND  lot_type IN ('PP', 'PB', 'PG')
  AND  lot_transn_time >= TO_CHAR(SYSDATE - 3, 'YYYYMMDD HH24MISS')
;

  ※ lot_transn_time 은 STRING('YYYYMMDD HH24MISS') 이라 문자열 비교로 자른다.
  ※ 최초 3개월 백필 시에는 마지막 조건만 바꾼다.
       AND lot_transn_time >= TO_CHAR(TRUNC(ADD_MONTHS(SYSDATE, -3), 'MM'),
                                      'YYYYMMDD HH24MISS')

3. 참고 (매칭표 확인 완료 사항)
================================================================================

(1) 날짜 계열 컬럼 타입 — 전부 STRING 이라 현행 python 파싱 그대로 쓴다.

    mc_lot (E / G)
      start_date, last_tkout_date, step_arrive_date, last_event_date  : STRING
    mi_equipment (B)
      eqp_status_change_time                                          : STRING
    mi_lot_transn_hist (L)
      lot_transn_time, recent_tkout_time                              : STRING
      tkin_date, process_start_date, process_finish_date               : TIMESTAMP
      tkout_date                                                       : DATE

    -> python 의 '숫자만 뽑아 yyyyMMddHHmmss 로 파싱' 로직을 손댈 필요가 없다.
       단 get_move 는 lot_transn_time(STRING)을 쓰므로 문자열 비교로 자른다.

(2) impala_insert_time 은 Impala 적재본 전용이라 Oracle 조회에 넣지 않는다.
    version_desc 는 Oracle 원본에도 있으므로 hold 조회에 포함한다.

(3) step_path 조인의 Oracle 성능
    Impala 에서는 이 조인이 전송량을 크게 줄였다(683만 -> 457만). Oracle 에서
    느리다면 조인을 빼고 생테이블로 받아 python 에서 거르는 쪽으로 되돌린다.
    (이것만 실측이 필요하다)
