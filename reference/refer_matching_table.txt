<fabplan Spotfire 조회 쿼리>
---------------------------------------------------------------------------
대상: PFR1 재공 중 order_seq 가 비어 있는 lot (= FabPlan lot).
      lot 속성 / grade / hold / 경과일 등은 기존 PFR1 경로를 그대로 쓴다.
      여기서 받는 것은 **스텝 경로(step path)** 를 만드는 데 필요한 원천뿐이다.

효율화 방침
  - SELECT * 를 쓰지 않는다. 실제 쓰는 컬럼만 뽑는다.
  - 서버(Oracle)에서 걸 수 있는 조건은 전부 서버에서 건다.
  - 정렬은 Spotfire / 파이썬 쪽에서 한다(ORDER BY 제거 → 조회 시간 단축).

QUERY_TIME 컬럼 (필수)
  기존 테이블과 마찬가지로 **원천 조회 시각**을 첫 컬럼으로 넣는다.
  이 컬럼이 없으면 s3 업로드 로그(upload_log)와 f3_load_log 의
  query_time 이 빈칸이 되어, 언제 조회된 데이터인지 알 수 없다.
    Oracle : TO_CHAR(SYSDATE, 'YYYY-MM-DD HH24:MI:SS')
    Impala : FROM_TIMESTAMP(NOW(), 'yyyy-MM-dd HH:mm:ss')
===========================================================================


--- A. PFR1_FABPLAN_STEP ---------------------------------------------------
-- 원천: SMICDC_P3NRD.STEP        (참고: SELECT * 기준 17초)
-- 쓰임: 공정별 스텝 경로. 연속 판정(delaytime / areaname / stepseq_type),
--       layer / area / eqptype / recipe / skiprule.
-- 줄이는 법
--   1) REVSTATE = 'Active' 만.
--   2) 60여 개 컬럼 중 12개만.
--      설비는 STEP.EQPGROUP 이 아니라 **TIP(trackinprevent) 조인**으로 만든다.
--        A.proc_id = B.process · A.stepseq = B.step · A.recipeid_eff = B.ppid
--      그렇게 찾은 설비를 (lot, stepseq) 로 묶어 EQPGROUP 을 구성한다.
--      CATEGORY 는 HOTLOT SKIP 판정에 쓴다.
--   3) stepseq_type 은 여기서 만들어 보낸다(파이썬 계산량을 줄인다).
--      3번째 글자부터 숫자가 아니면 '기타', 숫자뿐이면 '메인'.
SELECT TO_CHAR(SYSDATE, 'YYYY-MM-DD HH24:MI:SS')  AS QUERY_TIME,
       PROCESSID,
       STEPSEQ,
       CASE WHEN REGEXP_LIKE(SUBSTR(STEPSEQ, 3), '[^0-9]')
            THEN '기타' ELSE '메인' END           AS STEPSEQ_TYPE,
       AREANAME,
       EQPTYPE,
       LAYERID,
       CATEGORY,
       DESCRIPT,
       RECIPEID,
       DELAYTIME,
       SKIPRULE
FROM   SMICDC_P3NRD.STEP
WHERE  REVSTATE = 'Active'


--- B. PFR1_FABPLAN_NEWEINECNSPEC -------------------------------------------
-- 원천: SMICDC_P3NRD.NEWEINECNSPEC   (참고: SELECT * 기준 10초)
-- 쓰임: EIN / ECN / RCS 규제. 연속을 끊고 ppid / 설비를 제한한다.
-- 줄이는 법
--   1) 유효한 것만: 기간 안 + HOLDFLAG <> 'Y' + 잔여 카운트 조건.
--      (원본 파이썬이 하던 필터를 서버로 내린다)
--   2) 35개 컬럼 중 13개만.
SELECT TO_CHAR(SYSDATE, 'YYYY-MM-DD HH24:MI:SS')  AS QUERY_TIME,
       TYPE_                                      AS PEMS_TYPE,
       EINECNNO,
       PROCESSID,
       CONNECTTYPE,
       STEPSEQ,
       NEXTSTEPSEQ,
       LOTIDS,
       EQPIDS                                     AS PEMS_EQPIDS,
       CHAMBERIDS                                 AS PEMS_CHAMBERIDS,
       PPID                                       AS PEMS_PPID,
       COMMENT_                                   AS PEMS_COMMENT,
       ISSUEUSER                                  AS PEMS_USER,
       ISSUEDATE                                  AS PEMS_DATE,
       ECNRULE
FROM   SMICDC_P3NRD.NEWEINECNSPEC
WHERE  SYSDATE BETWEEN STARTTIME AND ENDTIME
  AND  HOLDFLAG <> 'Y'
  AND  (TOTALCOUNT = 0
        OR (TKINCOUNT < TOTALCOUNT AND TYPE_ IN ('EIN', 'RCS'))
        OR TYPE_ = 'ECN')


--- C. PFR1_FABPLAN_SELECTCONNECTSPEC ---------------------------------------
-- 원천: SMICDC_P3NRD.SELECTCONNECTSPEC   (참고: SELECT * 기준 13초)
-- 쓰임: EIN 연결 규칙(첫 EIN -> 다음 EIN -> 실제 적용 EIN).
-- 줄이는 법: 3개 컬럼이 전부이고, 적용값이 있는 행만.
SELECT TO_CHAR(SYSDATE, 'YYYY-MM-DD HH24:MI:SS')  AS QUERY_TIME,
       FIRSTEINECNNO,
       NEXTEINECNNO,
       SELECTEINECNNO
FROM   SMICDC_P3NRD.SELECTCONNECTSPEC
WHERE  SELECTEINECNNO <> '-'
