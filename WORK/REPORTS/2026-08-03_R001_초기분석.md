### 1-2. 설계서 검토

`docs/blueprint_fab_flow_monitor.md`(1359행) 전체를 검토했습니다.

**설계서의 강점 — 그대로 유지 권장**

- **시각 속성 1:1 매핑** (색=Line, 선종류=Lot Type, 위치=지표, 명도=Proc). 상세 비교 모드에서 패널당 12개 선이 겹치는 상황을 해석 가능하게 만드는 유일한 규칙입니다.
- **인과관계 확정 표현 금지**(§9.2, §23.5). 성과 Gap / 진행 제약 노출량 / 추정 손실 3단 분리는, 산식이 확정되지 않은 지금 상태에서도 화면을 정직하게 만들 수 있는 설계입니다.
- **§20 컴포넌트 트리 + §21 상태 모델**. 그대로 코드 구조로 옮길 수 있는 수준으로 구체적입니다.

**보완이 필요한 지점** — `STATUS.md` §4-4, §4-5로 정리했습니다.

## 4. 우려되는 일

`STATUS.md` §5에 상세 기재. 요약하면 다음 3건입니다.

1. **WAIT성 진행불가율의 원천 데이터가 보유 테이블 9개 어디에도 없음.** 설비 Status(Down/PM/Local)와 TIP 관련 테이블이 통째로 빠져 있어, FlowStack 5번째 패널과 Wait Block Analysis 전체가 Mock으로만 존재하게 됩니다. 추가 테이블 확보가 필요합니다.
2. **시계열 데이터 부재.** 현재 쿼리는 스냅샷 1회분입니다. 설계서 기본값은 최근 30일 시계열입니다. 일별 재공 스냅샷 테이블이 별도로 있는지 확인이 필요합니다.
3. **Layer 원천 미확정.** Lot Balance의 X축인데 `mc_lot`에 layer 컬럼이 없습니다. Phase 3의 전제 조건입니다.
